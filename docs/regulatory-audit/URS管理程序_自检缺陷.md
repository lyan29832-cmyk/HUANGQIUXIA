## 1.1 URS适用范围未覆盖改造类项目

**缺陷等级：** 主要缺陷

**缺陷描述：**

经查阅URS相关管理程序，其适用范围仅规定对拟购置的设备、设施或系统编制用户需求（URS），未对已投入使用系统的改造项目作出相应规定。改造项目至少包括设备重大升级、软件单独升级等使原确认状态可能发生改变的情形。程序中亦未见上述改造项目URS的提出部门、编制、审核、批准要求，以及与变更控制、再确认或再验证的衔接规定。

《药品生产质量管理规范（2010年修订）》附录《确认与验证》第十一条明确要求：企业应当对新的**或改造的**厂房、设施、设备按照预定用途和本规范及相关法律法规要求制定用户需求，并经审核、批准。同附录第十二条至第十四条进一步规定，设计确认应当证明设计符合用户需求；新的或改造的厂房、设施、设备需进行安装确认，并应根据用户需求和设计确认中的技术要求进行验收。现行程序将适用范围限定为“拟购置”，在文件层面将改造项目排除在URS管理之外，与上述条款不一致。

设备重大升级可能改变设备结构、功能、关键参数或与工艺的接口；软件单独升级属于计算机化系统变更。二者均可能影响预定用途、产品质量、数据完整性或GxP符合性。缺少经批准的用户需求，后续设计确认、安装确认、运行确认、性能确认（或再确认）及变更验证即失去比对基准，无法证明改造后系统仍符合预定用途。该情形属于程序性、系统性缺口，不限于单一项目或单一设备。

**不符合：**

1. 《药品生产质量管理规范（2010年修订）》第八十三条：设备的设计、选型、安装、改造和维修应当符合预定用途。
2. 同规范附录《确认与验证》第十一条：企业应当对新的或改造的厂房、设施、设备按照预定用途和本规范及相关法律法规要求制定用户需求，并经审核、批准。
3. 同附录第十二条：设计确认应当证明设计符合用户需求，并有相应的文件。
4. 同附录第十三条、第十四条：新的或改造的厂房、设施、设备需进行安装确认；企业应当根据用户需求和设计确认中的技术要求对厂房、设施、设备进行验收并记录。
5. 同规范附录《计算机化系统》第十七条：计算机化系统的变更应当根据预定的操作规程进行，操作规程应当包括评估、验证、审核、批准和实施变更等规定；重大变更应当验证。软件单独升级为计算机化系统变更，其需求应可追溯至经批准的用户需求。

**判定逻辑：**

1. 用户需求是确认与验证的起点，也是验收和再确认的基准。
2. 法规对“新的”和“改造的”系统提出同等的用户需求要求，并不以是否新购为划分条件。
3. 设备重大升级、软件单独升级属于改造或系统变更，可能使已确认状态失效。
4. 现行程序范围仅覆盖“拟购置”，改造类项目在程序上无URS依据。
5. 因此，该程序不能保证改造后系统的预定用途得到识别、批准和确认，构成主要缺陷。
